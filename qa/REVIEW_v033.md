# v0.33 — guarded CLI floor lifecycle

This pass completes top-floor creation/removal in the CLI. The web editor retains its existing basement, insertion, duplication and reorder controls.

- `floor.add-top` uses an explicit new ID and the current top-floor ID as an anchor. It shares the web stack helper and accepts labels, dimension overrides and initial automatic-surface switches. Author contents and incoming stairs in subsequent operations before whole-transaction validation.
- `floor.remove-top` requires explicit permission within the transaction to remove owned contents and, independently, incoming stairs. It cannot delete the last floor. Reports list exactly which owned entities and connections were removed; no reference reassignment or inferred ownership is introduced.
- Structural, stair, platform and slab-coverage reports match floor IDs rather than assuming matching array lengths. Added/removed floors have nullable before/after entries. Operation inventory remains chronological even for a net-zero edit. No failed candidate is published.
- Independent manual roofs, floors and ceilings retain their authored absolute heights. Effective stack changes retain the dimension-edit alignment warning and strict-mode rejection. Automatic geometry is regenerated by the existing exporter.

The new CPU/CLI suite includes deterministic defaults, explicit overrides, final-state repair, invalid fields/IDs, content/stair guards, orphan reconnection, floor-owned removals, independent-height review, web reload/export parity, dry-run/save consistency and rejection without output. The paired recipes add a third floor to the existing north-ramp example and remove it again. The suite makes 11 CLI calls; removal restores the original scene bytes exactly.

The new Godot suite makes 10 further CLI calls to author/export five cases. Its 60 physics rays check full and partial top footprints, roof and ceiling exposure, stair slab holes, unchanged lower-story bands, new upper wall skirts and removed-story collision. It checks separate exterior/interior lighting-shell nodes, story organization and empty material slots. Both removal paths restore the baseline scene byte-for-byte.
